xfmpress v0.4.10：清掉已知问题清单上的三个 Markdown 边角案例

3 分钟阅读 # xfmpress# 更新日志

每个 Markdown 实现都有一份「已知问题」清单，里面躺着那些触发条件刁钻、但一旦撞上就很恼人的边角案例。v0.4.10 一次清掉了 xfmpress 的三个，全部集中在 lib/engine/markdown.js，且都以 CommonMark 规范为准绳。

这一版在解决什么

这三个案例有一个共同点：都发生在「两种语法在同一处相遇」的地方——列表项里出现代码块或引用、脚注定义后面紧跟嵌套列表、段落中间出现链接引用定义。旧版本的解析器在这些交界处贪心或误判，产出的 HTML 与你写下的意图不一致。修复的原则是：凡有歧义，按 CommonMark 裁决。

变了什么

Fixed

  • 列表项内的块级内容按块渲染。旧版把 - 安装： 后面缩进的代码围栏拍平成一段文本（<li>安装： npm i -g xfmpress</li>），缩进的 > 则被转义成 &gt;。现在列表项按内容缩进收集自己的内容，把引用、围栏代码、::: 容器、分隔线交给块解析器，产出 <li><p>安装：</p><div class="code-block">…</div></li> 这样的正确结构。- 标题 + --- 也保留 Setext 标题的含义，不再变成分隔线。
  • 脚注的块级内容要求规范的 4 空格缩进。旧规则接受 2 个空格并最多反缩进 4 格，导致脚注定义后面一个两空格缩进的嵌套列表被整个吞进脚注。现在 4 空格（或一个制表符）表示块级内容，1–3 空格仍表示「同一段落的下一行」（已有散文不会因此断开），脚注后未缩进的段落仍是普通段落。
  • 链接引用定义不再打断段落。旧版 collectDefinitions 会把全文里每一行 [a]: /url 都抽走，段落中间出现的定义会把段落切成两半还少一行。现在只在段落开头收集定义——这也是 CommonMark 的要求——段落中间的 [a]: /url 保持字面文本，也不会注册引用。
  • 默认主题和 docs 主题：含块级子元素的列表项不再因子元素 p 的外边距多出首尾空白。

Tests

测试从 128 增加到 131，覆盖列表项内的块级内容（引用 / 围栏 / callout）、段落内的引用定义、脚注缩进的边界。

升级要不要动手

不需要。修复只影响过去被错误渲染的写法——如果你从没在列表项里放过代码块，这版对你完全透明；如果你曾被迫绕开这些写法，现在可以按直觉写、按 CommonMark 渲染了。Markdown 引擎支持范围的完整说明见 Markdown 教程。
