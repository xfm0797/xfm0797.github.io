xfmpress v0.4.0：内置搜索、列表分页与一批阅读体验升级

4 分钟阅读 # xfmpress# 更新日志

v0.4.0 是 xfmpress 一个明显变「完整」的版本。过去你需要自己接第三方搜索、手写分页逻辑，或者忍受一些阅读上的小别扭，这一版把这些都变成了内置能力，而且是零依赖的实现——不会给你的站点增加任何运行时包袱。

这一版在解决什么

静态站点的三个常见痛点在这一版被逐个处理：访客找不到内容（没有搜索）、文章多了首页列表无限拉长（没有分页）、阅读细节粗糙（代码没法一键复制、图片点击没有反馈、不知道文章读到哪了）。v0.4.0 用三个 Added 条目分别回应了它们。

变了什么

Added：搜索、分页、阅读体验

  • 内置搜索：新的 search 插件把所有内容页编译成一份 search.json（含标题、描述、标签和正文前若干字符，可用 search.maxChars 调整），两套主题都内置了 Ctrl/⌘+K（或 /）唤起的搜索面板，首次使用时才懒加载索引，过滤完全在客户端完成。首页、分类页、索引页和分页页默认不进索引；某页想退出，在 front-matter 写 search: false 即可。
  • 列表分页：配置 pagination: { perPage } 后，文章列表会被切成真正的静态页面 /page/2/、/page/3/……并带上「上一页 / 页码 / 下一页」的分页器（页码过多时省略号折叠）。第 1 页就是首页本身，模板在任何位置读到的都是同一套 pagination 结构。如果首页布局不渲染文章列表（比如 docs 主题）会自动跳过分页；分页页也不会混入 RSS、导航分组、上一篇/下一篇和搜索索引。
  • 阅读体验：两套主题通过共享的 ux.js 获得了代码块复制按钮、图片点击放大、文章阅读进度条，外部链接统一新窗口打开并带上 noopener noreferrer。Markdown 图片现在默认 loading="lazy"、decoding="async"。

Changed：site.base 改由引擎处理

以前要靠构建期补丁脚本 scripts/pages-base.js 来给链接加前缀，现在引擎自己在渲染完成后统一处理：页面 HTML 里所有根绝对路径的 href/src（模板、Markdown 链接、原始 HTML 全覆盖）会被加上 site.base 前缀且只加一次；sitemap、RSS 和搜索索引里的 URL 走同一个 helper；xfm dev 也会在配置的前缀路径下服务站点。磁盘上的输出路径不变，GitHub Pages 工作流改为直接传 SITE_BASE 给构建。

一个小行为差异要注意：robots.txt 现在只有在配置了 site.url 时才会输出 Sitemap: 行。

升级要不要动手

没有破坏性变更。如果你之前依赖 scripts/pages-base.js 做子路径部署，可以直接删掉它，改用 site.base 配置——引擎接管后效果一致且覆盖更全。想启用搜索就在插件里加上 search，想分页就配 pagination.perPage，两者都是纯增量。如果你刚上手，建议先看快速开始再回来配置这些。
