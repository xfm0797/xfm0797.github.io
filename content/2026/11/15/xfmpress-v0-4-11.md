在写作时给列表项之间留一个空行，是让长列表更易读的常见做法——但旧版 xfmpress 会因此把一个列表劈成两个。v0.4.11 是 Markdown 引擎的松散列表专项修复，改动全部在 `lib/engine/markdown.js`，目标是让「带空行的列表」按 CommonMark 的方式工作。

## 这一版在解决什么

空行在 Markdown 里有双重身份：它既是段落分隔符，又是列表项之间的呼吸空间。旧版引擎把空行一律当作「列表结束」处理，导致三种损伤：`ol` 编号被拆断、嵌套列表结构错乱、依赖 `li + li` 选择器的 CSS 失效。v0.4.11 重新划定了空行在列表内外的边界。

## 变了什么

### Fixed

- **列表项之间的空行不再拆散列表**。`- a` + 空行 + `- b` 此前产出两个独立的 `<ul>`，`ol` 编号、嵌套列表和所有针对 `li + li` 的 CSS 都会被破坏。现在以空行分隔的列表项保持在同一个列表里。
- **列表项内空行后的内容不再掉出 `li`**。`- 第一段` + 空行 + ` 第二段` 此前把第二段渲染在 `li` 之外（缩进还是错的）。现在空行后的缩进内容归属该列表项，由块解析器渲染——后续段落、子列表、围栏代码块、引用都正常工作。

### Changed

- **实现 CommonMark 的紧/松列表规则**：只要任意两个列表项之间有空行，或某个列表项内部含空行，整个列表的每个段落都会包进 `<p>`；紧凑列表不受影响（仍是 `<li>a</li>`），含块内容的列表项保留它本来就该有的 `<p>`。列表后的空行仍然结束列表，空行之后仍不允许惰性续行。
- **属于外层列表的空行归还外层**。例如 `- a` / `  - b` / 空行 / `- d` 中，那个空行属于外层列表，不再把内层列表标记为松散。

## 升级要不要动手

不需要改配置，但渲染结果会变化：如果你的 CSS 针对 `li > p` 写了间距样式，过去「从不出现」的 `<p>` 现在会在松散列表里出现，视觉效果可能和旧版不同——这通常意味着更正确的间距，但值得扫一眼。之前为了绕开这个 bug 而删除空行改紧凑列表的写法，可以改回原样了。Markdown 引擎的行为细节见 [Markdown 教程](/2026/11/21/xfmpress-markdown/)。
